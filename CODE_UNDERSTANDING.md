# VoltArena — Code Understanding & Codebase Tour

## 1. Introduction
This guide provides an engineering walkthrough of the VoltArena codebase. It is designed to help engineers, contributors, and auditors rapidly understand how the components, scripts, mechanics, and systems are structured and interconnected.

## 2. Directory Taxonomy

The repository is structured into distinct, decoupled domains:

```
├── .godot/                     # Engine import cache (generated by container)
├── artifacts/                  # Production certification logs and JSON reports
├── export/                     # Compiled builds (web, linux, windows, android, dist)
├── games/                      # The eight playable 3D games
│   ├── arena-fps/              # Game 1: Iron Crucible
│   ├── kart-racing/            # Game 4: Drift Storm
│   ├── rocket-car/             # Game 3: Nitro Kick
│   ├── subway-survival/        # Game 2: Metro Siege
│   ├── skybound-odyssey/       # Game 5: Skybound Odyssey
│   ├── roboforge-arena/        # Game 6: RoboForge Arena
│   ├── wildcircuit/            # Game 7: WildCircuit
│   └── strike-vector/          # Game 8: Strike Vector
├── launcher/                   # Master Cyberpunk UI launcher
├── platform/                   # Deployment configurations (web _headers, nginx)
├── scripts/                    # Automation scripts (.sh and .ps1) for Podman
├── shared/                     # Cross-game core singletons, UI, platform, and physics
└── tests/                      # Automated unit, acceptance, responsive, and benchmark suites
```

## 3. Detailed Component Deep-Dive

### 3.1 Shared Foundation & Platform Subsystems (`shared/`)

#### `shared/platform/platform_capabilities.gd`
* Detects Web (WASM/WebGL2), Windows x86_64, Android ARM64, Linux, macOS, and iOS environments.
* Computes safe-area insets from `DisplayServer.get_display_safe_area()`.
* Categorizes viewports by aspect ratio (16:9, 16:10, 18:9, 19.5:9, 20:9, 4:3, 21:9).
* Enforces minimum $48\text{dp}$ touch target dimensions.

#### `shared/platform/input_profile.gd`
* Translates semantic actions into dynamic glyphs across KBM, gamepad, and touch controls.
* Provides genre mappings for `GENRE_FPS`, `GENRE_RACING`, `GENRE_ROCKET_CAR`, `GENRE_PLATFORMER`.

#### `shared/platform/graphics_profile.gd`
* Manages Low, Medium, High, Ultra, and Auto graphical scalability presets.
* Enforces the invariant: `Engine.physics_ticks_per_second == 60` across all presets.

#### `shared/input/touch_controls.gd`
* Renders genre-adaptive touch controls (dual sticks, pedals, triggers).
* Automatically hides on desktop/KBM environments.

#### `shared/combat/health_component.gd`
* An autonomous combat component attachable to any entity (Player, Bot, Mutant, Soldier).
* Encapsulates health ($100.0$) and armor ($100.0$) with absorption calculation.
* Emits decoupled signals: `health_changed`, `armor_changed`, `damage_taken`, `died`.

#### `shared/audio/audio_manager.gd`
* Synthesizes audio waveforms directly into Godot `AudioStreamWAV` buffers using trigonometric formulas and noise generators:
  * Generates procedural sound effect types: `laser`, `shotgun`, `explosion`, `hit`, `engine`, `turbo`, `powerup`, `ambient`.
  * Instantiates 3D positional audio emitters (`AudioStreamPlayer3D`) with distance attenuation curves.

#### `shared/graphics/material_generator.gd`
* Factory pattern generating PBR materials: emissive glow, structural metals, hazard stripes, terrain, and glass.
* Caches materials in an internal Dictionary to eliminate redundant GPU state changes.

### 3.2 Game 1: Iron Crucible (`games/arena-fps/`)
* **`player/fps_player.gd`**: CharacterBody3D FPS locomotion with sprint, crouch, jump, air drift, dynamic view bobbing, and spring recoil recovery.
* **`weapons/weapon_base.gd`**: Standardized raycast and projectile shooting for Pulse Rifle, Scatter Cannon, Rail Driver, Grenade Launcher, Plasma Cutter.
* **`ai/arena_bot.gd`**: Autonomous bots with patrol waypoints, line-of-sight raycasts, and strafe combat.
* **`maps/arena_map_generator.gd`**: Procedurally generates multi-level arenas (Citadel, Foundry, Sektor) in $< 1\text{ms}$.

### 3.3 Game 2: Metro Siege (`games/subway-survival/`)
* **`game/wave_director.gd`**: Manages 10-wave survival loop: `Wave Active` $\to$ `Intermission Scavenge` $\to$ `Next Wave`.
* **`enemies/`**: Crawler (swarmer), Stalker (flanker), Brute (armored tank), Spitter (acid artillery), BioColossus (Wave 10 boss).

### 3.4 Game 3: Nitro Kick (`games/rocket-car/`)
* **`vehicle/car_controller.gd`**: Canonical $-Z$ forward hierarchy, 4 archetypes (*Apex Spectre*, *Dune Raider*, *Titan Enforcer*, *Volt Pulse*), double jump, boost, and aerial pitch/yaw/roll.
* **`ball/ball.gd`**: Continuous collision detection (CCD), single-impulse integration, and `reset_ball()` API.
* **`arena/rocket_arena.gd`**: Regulation colosseum ($110\text{m} \times 64\text{m} \times 20\text{m}$) with $45^\circ$ octagonal corners, acrylic walls, post frames, and net geometry.
* **`ai/car_ai.gd`**: Tactical roles (`STRIKER`, `SUPPORT`, `DEFENDER`, `GOALKEEPER`) with predictive lead interception and aerial jumps.

### 3.5 Game 4: Drift Storm (`games/kart-racing/`)
* **`kart_racing_main.gd`**: 11-stage scene state machine (`DriftHome -> ModeSelect -> TrackSelect -> VehicleSelect -> RaceSetup -> Confirm -> Loading -> Grid -> Countdown -> Racing -> Finished`). Complete pre-race isolation hiding the 3D track, player kart, and AI opponents until race launch.
* **`ui/drift_storm_hud.gd`**: Responsive full-screen pre-race hub with dynamic vector spline preview canvas, 5-vehicle radar bars, and an always-visible bottom navigation bar with $\ge 48\text{dp}$ touch targets guaranteed unclipped across all 9 viewports.
* **`kart/kart_controller.gd`**: 4-wheel raycast suspension system, rolling wheel rotation, steering yaw, 3-tier drift boost sparks, and nitrous surge.
* **`tracks/race_spline.gd` & `tracks/track_generator.gd`**: Single authoritative spline for 6 global circuits (Volt Speedway, Sunset Coast, Canyon Run, Skyline Drift, Alpine Rush, Storm Harbor) with verified 0 corridor encroachments.

## 5. Design Patterns Utilized

1. **Singleton Pattern**: Core managers (`GameManager`, `EventBus`, `SaveManager`, `PlatformAdapter`, `QualityManager`, `InputManager`) are autoloaded globally.
2. **Observer / Pub-Sub Pattern**: Modules communicate through `EventBus` signals rather than hard-coded coupling.
3. **Component Pattern**: `HealthComponent` encapsulates damage and armor logic across all entities.
4. **State Machine Pattern**: 11-stage state machine in `KartRacingMain`, 10-state HFSM in `StrikeAIBase`, and match loops in `WaveDirector` and `RocketCarMain`.
5. **Authoritative Spline Pattern**: `RaceSpline` provides the single ground truth for road geometry, AI, HUD minimap, and lap tracking in `DriftStorm`.
6. **Strategy Pattern**: `InputProfile` and `GraphicsProfile` encapsulate device-specific input and visual rendering policies.
