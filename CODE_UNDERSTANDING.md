# VoltArena — Code Understanding & Codebase Tour

## 1. Introduction
This guide provides an engineering walkthrough of the VoltArena codebase. It is designed to help engineers, contributors, and auditors rapidly understand how the components, scripts, mechanics, and systems are structured and interconnected.

---

## 2. Directory Taxonomy

The repository is structured into distinct, decoupled domains:

```
├── .godot/                     # Engine import cache (generated by container)
├── artifacts/                  # Production certification logs and JSON reports
├── export/                     # Compiled builds (web, linux, windows, android, dist)
├── games/                      # The four playable 3D games
│   ├── arena-fps/              # Game 1: Iron Crucible
│   ├── kart-racing/            # Game 4: Drift Storm
│   ├── rocket-car/             # Game 3: Nitro Kick
│   └── subway-survival/        # Game 2: Metro Siege
├── launcher/                   # Master Cyberpunk UI launcher
├── platform/                   # Deployment configurations (web _headers, nginx)
├── scripts/                    # Automation scripts (.sh and .ps1) for Podman
├── shared/                     # Cross-game core singletons, UI, and physics
└── tests/                      # Automated unit, acceptance, and benchmark suites
```

## 3. Detailed Component Deep-Dive

### 3.1 Shared Foundation (`shared/`)

#### `shared/combat/health_component.gd`
* An autonomous combat component attachable to any entity (Player, Bot, Mutant).
* Encapsulates health ($100.0$) and armor ($100.0$) with absorption calculation:
  ```gdscript
  var absorbed = final_dmg * armor_absorption_ratio
  var to_armor = min(current_armor, absorbed)
  current_armor -= to_armor
  final_dmg -= to_armor
  current_health = max(0.0, current_health - final_dmg)
  ```
* Emits decoupled signals: `health_changed`, `armor_changed`, `damage_taken`, `died`.

#### `shared/audio/audio_manager.gd`
* Synthesizes audio waveforms directly into Godot `AudioStreamWAV` buffers using trigonometric formulas and noise generators:
  * Generates 8 algorithmic procedural sound types: `laser`, `shotgun`, `explosion`, `hit`, `engine`, `turbo`, `powerup`, `ambient`.
  * Instantiates 3D positional audio emitters (`AudioStreamPlayer3D`) with distance attenuation curves.

#### `shared/graphics/material_generator.gd`
* Factory pattern generating PBR materials:
  * Emissive glow materials (`neon_cyan`, `neon_magenta`, `neon_orange`, `neon_green`).
  * Structural architectural materials (`dark_hull`, `metal_floor`, `hazard_stripe`).
  * Caches materials in an internal Dictionary to prevent redundant GPU pipeline states.

### 3.2 Game 1: Iron Crucible (`games/arena-fps/`)

* **`player/fps_player.gd`**:
  * Inherits `CharacterBody3D`.
  * Manages mouse look pitch/yaw with clamping ($-89^\circ$ to $+89^\circ$).
  * Implements dynamic weapon bobbing and procedural spring recoil recovery.
  * Manages weapon switching ($1-5$ keys or mouse scroll).
* **`weapons/weapon_base.gd`**:
  * Base class for weapons. Computes camera raycast origins, spread offsets, and handles hitscan raycasting or ballistic projectile instantiation.
  * Subclasses: `grenade_launcher.gd`, `plasma_cutter.gd`, `rail_driver.gd`, `scatter_cannon.gd`.
* **`ai/arena_bot.gd`**:
  * Extends `AIBase`.
  * Evaluates patrol waypoints and line-of-sight raycasts to target the player.
  * Engages in strafing combat maneuvers, checks firing cooldowns, and executes respawn timers when killed.
* **`maps/arena_map_generator.gd`**:
  * Procedurally constructs the multi-level arena geometry, catwalks, ramps, pillars, and jump pads in $< 1$ millisecond.

### 3.3 Game 2: Metro Siege (`games/subway-survival/`)

* **`game/wave_director.gd`**:
  * Manages the survival game loop: `Wave Active` $\to$ `Intermission Scavenge` $\to$ `Next Wave`.
  * Scales mutant spawn budgets exponentially ($6 \times 1.25^{\text{wave}}$).
  * Distributes enemy archetypes (Wave 1: Crawlers; Wave 2+: Stalkers; Wave 3+: Brutes).
* **`enemies/crawler.gd`**: High-speed melee swarmer that charges the player and executes a forward leap when within 4.0 meters.
* **`enemies/stalker.gd`**: Mid-range flanking mutant that circles around player line-of-sight before lunging.
* **`enemies/brute.gd`**: Heavy armored tank with high health that triggers an area-of-effect ground pound attack when close to the player.
* **`maps/subway_generator.gd`**: Procedurally generates subway tracks, passenger boarding platforms, track ballasts, tunnel arches, and lighting fixtures.

---

### 3.4 Game 3: Nitro Kick (`games/rocket-car/`)

* **`vehicle/car_controller.gd`**:
  * Simulates responsive 3D vehicular driving mechanics with raycast-based wheel suspension principles.
  * Supports throttle, braking/reversing, double-jump vertical thrusters, and nitrous boost with particle exhaust.
  * Handles both human player input and AI bot input through unified `handle_ai_input()`.
* **`ball/ball.gd`**:
  * Simulates a physics ball with elastic bounce restitution ($0.82$), rolling drag, and impulse momentum transfer on vehicle collision.
* **`arena/rocket_arena.gd`**:
  * Builds the symmetrical futuristic stadium with curved corner banked walls and goal detector zones.
* **`rocket_car_main.gd`**:
  * Manages match rules: goal detection triggers stadium sirens, awards points to scoring team, and initiates kickoff resets with 1.5-second countdown holds.

---

### 3.5 Game 4: Drift Storm (`games/kart-racing/`)

* **`kart/kart_controller.gd`**:
  * Arcade vehicle physics model featuring drift mechanics: holding drift locks the rear axle into a slide angle.
  * Accumulating drift charges 3 tiers of boost:
    1. Blue Sparks ($1.2\times$ boost)
    2. Orange Sparks ($1.5\times$ boost)
    3. Purple Sparks ($1.9\times$ boost)
  * Releasing drift triggers a nitrous surge.
* **`tracks/track_generator.gd`**:
  * Procedurally builds a banked 3D closed-loop circuit track using trigonometric curves.
  * Generates track barriers, start/finish gantries, racing curbs, and item box powerup placements.
* **`tracks/checkpoint.gd` & `game/race_manager.gd`**:
  * Implements sequential checkpoint gating. A player cannot register Checkpoint $N+1$ without triggering Checkpoint $N$, completely preventing reverse driving or shortcut cheating.

## 4. Design Patterns Utilized

1. **Singleton Pattern**: Core managers (`GameManager`, `EventBus`, `SaveManager`) are autoloaded globally.
2. **Observer / Pub-Sub Pattern**: Gameplay modules communicate with HUD and Audio through `EventBus` signals rather than hard-coded references.
3. **Component Pattern**: `HealthComponent` encapsulates combat damage logic and can be attached to any node.
4. **Factory Pattern**: `MaterialGenerator` synthesizes and caches materials dynamically.
5. **State Pattern**: `WaveDirector` transitions between `PREPARING`, `ACTIVE_WAVE`, `INTERMISSION`, and `GAME_OVER`.
